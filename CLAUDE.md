# Eleusinia

Peer-to-peer chat and voice calls for desktop with no central server: a Discord/TeamSpeak-style app
where every message and call goes directly between the people involved. Electron + React + TypeScript.
See `README.md` for features, known limits and the roadmap.

## Commands

| Command | Use |
|---|---|
| `npm install` | Install; the postinstall also downloads the Electron binary (~100 MB). If `npm run dev` says `Electron uninstall`, run `npx install-electron` |
| `npm run dev` | Run with hot reload |
| `npm run typecheck` | `tsc --noEmit` over `src` and `test` |
| `npm test` | Vitest: `test/node.test.ts` runs the whole node layer against a local test DHT, no Electron; `test/callstate.test.ts` covers call reconnect decisions with a fake connection; `files.test.ts` file transfers between in-memory peers; `jingles.test.ts` the sounds; `idcard.test.ts` the offline ID cards; `netsim.test.ts` the bad-line simulator; `groups.test.ts` group ownership, signed adds, removal and signed edits; `sealed.test.ts` sealed friend requests; `updatesig.test.ts` the update signature; `steam.test.ts` Steam's text and binary files, the registry and the process list; `activity.test.ts` what may be shared, checking a friend's activity and the picture allowlist; `gsi.test.ts` CS2 payloads, what of a match is shared, and the local server for both games (token, size cap, the config files, a taken port, Dota's launch option); `dota.test.ts` Dota 2 payloads (playing, dead, paused, spectating), what is shared and the hero and item pictures; `destiny.test.ts` a Destiny 2 profile with its Manifest definitions (raid, Crucible, orbit), what is shared, checking a friend's and the bungie.net pictures; `bungie.test.ts` linking through `test/fake-bungie.mjs` (a stand-in for bungie.net, also used by the smoke run), renewing, revoked links, cancelling; `selfupdate.test.ts` the macOS and Linux swap-in, its rollback and cleanup; `video.test.ts`, `quality.test.ts`, `devices.test.ts`, `relay.test.ts`, `hotkeys.test.ts` cover the other pure logic |
| `ELEUSINIA_STRESS=1 npx vitest run test/stress.test.ts` | A group of 16 (`ELEUSINIA_STRESS_MEMBERS` for more) on a local test DHT, skipped otherwise: everyone writing at once, bounded links, presence, a 600-message flood, a rename and a late joiner paging back; `ELEUSINIA_STRESS_LOG=<file>` keeps the timings (vitest shows the console only for failing tests). 32 members took about 150 s |
| `npm run smoke` | Builds, then drives three real app windows on a **local test DHT** (passed to the app as `ELEUSINIA_BOOTSTRAP`, which is off unless set): setup, friend search, chat, sharing a picture and a file, a voice call (with its sounds: caller tune, ring, join, mute, deafen, leave; and, on direct routes, the chat link closing mid-call through the test-only `dropLink`, which `index.ts` allows only on a local test DHT, while the call goes on), hotkeys, screen sharing (with computer sound on Windows), a camera, offline delivery, a problem report and a renderer crash reaching a test inbox it starts itself (~2 min, opens windows; the microphone and camera are Chromium's fake devices, and screen sharing only ever captures the test's own windows; what each connection receives is read with `getStats` through a wrapped `RTCPeerConnection`; hotkeys are tested by injecting F23/F24 key presses system-wide, keys no ordinary keyboard has) |
| `npm run dist` | Windows installer into `dist/` (never published from a PC: releases come from `.github/workflows/release.yml` on every push to `main` that changes the app, numbered one past the newest release tag in `package.json`'s series, built on Windows, macOS and Linux runners and published together in one `gh release create` step; `.github/workflows/check.yml` tests and builds all three on every push to `test`) (electron-builder; native modules stay unpacked, `npmRebuild` off since they ship prebuilt). Run the smoke against it with `ELEUSINIA_SMOKE_EXE=dist/win-unpacked/Eleusinia.exe node test/smoke.mjs` |
| `ELEUSINIA_NO_DIRECT=1 npm run smoke` | Same, but direct call routes are withheld so the call must go through the relay |
| `ELEUSINIA_SMOKE_RELAYED=1 npm run smoke` | Same build, a shorter run: Ann and Bob start with `ELEUSINIA_STRICT=1` (testing only: hyperdht settings that make their direct connections fail for real on the local DHT) and `ELEUSINIA_NO_DIRECT=1`, so their chat and voice call can only go through Cy relaying; checks screen video is held back |
| `ELEUSINIA_TEST_NET="delay=150,jitter=30,loss=0.03,burst=4"` | Testing only: a simulated bad line on relayed call packets (`src/shared/netsim.ts`, Gilbert-Elliott burst loss, delay, jitter, `outage=30:8`), applied in `node.ts` where the relay sends; pair it with `ELEUSINIA_NO_DIRECT=1` |
| `.env.local` with `MAIN_VITE_BUNGIE_API_KEY`, `MAIN_VITE_BUNGIE_CLIENT_ID`, `MAIN_VITE_BUNGIE_CLIENT_SECRET` | Bungie.net's app key (from bungie.net/en/Application, confidential client, return URL `https://mmhfn1.github.io/eleusinia/bungie/`) for linking Destiny 2 in `npm run dev` and local builds; ignored by git. Releases take it from the `BUNGIE_*` secrets. Without it, linking says it is not available |
| `ELEUSINIA_SMOKE_SHOTS=<folder> npm run smoke` | Same, also saving screenshots of a few views (the activity cards, Settings → Activity) to look at |
| `ELEUSINIA_SMOKE_PUBLIC=1 npm run smoke` | Same, over the **public** DHT, for an occasional real-network check (slower, and flaky when the DHT is) |

Two identities on one machine: give each its own data folder with `ELEUSINIA_DATA`
(PowerShell: `$env:ELEUSINIA_DATA = "C:\temp\eleusinia-b"; npm run dev`).

Before calling a change done, run typecheck and `npm test`; for anything touching calls or connection
setup, also run the three smoke modes (plain, `ELEUSINIA_NO_DIRECT=1`, `ELEUSINIA_SMOKE_RELAYED=1`).

## Architecture

| Path | Role |
|---|---|
| `src/main/index.ts` | Electron main: window, identity (ed25519 key, encrypted with `safeStorage` when available; one that cannot be unlocked, such as a data folder copied from another computer, offers a new identity and keeps the old file as `identity-unreadable-<time>.json`; the data folder is owner-only, `privateDir`), and one IPC handler `call(method, ...args)` that forwards to the node |
| `src/main/node.ts` | Friends (requests go both over a direct link and, for peers that can never link, as announcements on `requestTopic(key)` checked every 30 s, with each profile published as a signed DHT record), groups, message logs and their sync, settings, call signaling (`signal`, `relayOpen`, `relayClose`). Logs stay on disk with as many recently used conversations in memory as fit in 50,000 messages (`keepMsgs`; the one in use always stays); `history(conv, limit)` returns the newest messages, from a time-sorted copy made once per change (`sorted`). History after a key theft: `confirmed` keeps, per conversation and peer, the most of each author's messages that peer ever confirmed, and nothing at or below it is sent to that peer again (kept out of state.json in `confirmed/<conv>.jsonl`: a receipt appends `{ k, h }` with only the authors it raised, `writeConfirmed` compacts each file at start and after a prune, an older state.json's copy moves there at start); a peer asking below it is told (`held`) and writes a `{ skip }` line to its log so new messages still arrive (`heldFrom` in sync.ts accepts that only for the sender's own messages and ours, so no member can make us drop someone else's). Our own numbering carries on after `acked` (what friends confirmed of ours, `acked`, kept in state.json) when the log holds less, so a message written after losing the logs is not taken for one they already have. A friend who tells us over a link that they removed us is noted in `unfriended`, and their DHT acceptances, which outlive the removal by up to ~20 min, are not believed for 30 min (`STALE_ACCEPT`). A group message, and every 5 s our receipt for it (`receipts`), goes on to only 3 random linked members (`forwardTo` for messages, 0 in the test that proves asking works), not all of them; a member it missed sees from someone's receipt that it lacks something and asks (at most every 5 s per peer, `askedFor`). `changed()` saves through `saveSoon` (within 2 s, flushed by `destroy`) and pushes through `pushSoon` (100 ms), so a burst of changes is one write and one state push; a greeting with an unchanged profile writes nothing. A group change received is passed on to 3 random linked members, like messages, not to everyone. Bounded links: we dial friends, whoever we have something for (`demand`: a call signal addressed to them, a file only they have, `files.want`) and per group `groupLinks` (8) members picked by a hash of both keys (`linkPick`, further down the list only past picks whose dial failed, at most 24 tried, so a burst of first dials stays at 8), not every member; a link we dialed and no longer need closes after 10 min (`closeIdle`: never friends, picks, a call's relay port, a file transfer). Members we are not linked with are known online from signed presence notes (`src/main/presence.ts`, `createPresence`; `signPresence`/`verifyPresence` in sync.ts; also sent within 2 s when a group reaches us or gains someone, `announceSoon`; ours every minute and on joining or leaving a group call, `ourCall`; passed on to 3 linked members sharing a group with the author; kept 3 min, `State.present`; at most every 20 s, every 10 s when the profile changed, every second when the call changed; dropped at once when our own link with them closes, `gone`); each note carries the author's `profileVersion`, and a member not linked with us whose version differs from ours (`profileV`, set from greetings and cards) has their card fetched again (`refreshCard`: a new version at most every 10 s, an unchanged card retried 3 times 10 s apart, since the new one may not be on the DHT yet); a note's call reaches the page as that member's `join`/`leave` (`callMoved`), and call.ts answers someone in its call without a known version with a `join` addressed to them, which makes the node dial them; joining a call also sends `join` to each person already in it who is not online for us (not linked). The smoke run starts every window with `ELEUSINIA_TEST_GROUP_LINKS=0` (honoured only on a local test DHT), so Bob and Cy, not friends, never link and their group call goes through exactly that. Pictures live apart in `pictures/<id>` (named by hash; state.json holds `pic:<id>`, `toRef`/`fromRef`, unreferenced ones deleted at start) and reach the window as `eleusinia-pic://<id>` (`picUrl` in `state()`, served by index.ts through `picture`). Catch-ups go a page at a time (`CATCHUP_PAGE` 200, none while 1 MB is unsent on the link; `sentUpTo` holds back only receipts, for 10 s); a message counts as unread only if written after the group reached us (`joinedAt`); a group that reached us after this change takes a shallow start (`shallow`: our `have` says `tail`, and a member holding more than `SHALLOW` (100) of an author we hold nothing of starts us at their newest 100; that page's first message of each such author says `start`, and only that one is taken past a gap, logged as a `{ tail }` line: a message that merely overtook earlier ones, as when everyone writes at once, is never a start); a torn last line (a write cut short) is ended with a line break when the log is first read (`msgsOf`), so the next message is not glued to it, and older history comes on request (`older`: a page at or below each author's tail, each author's run by number, newest first, merged by time; one step down per message, `history().earlier` while any is left; members answer one request a second); a message's time must be a whole number a Date can hold (`verifyMsg`) and is turned away while more than 10 min ahead (`EDIT_AHEAD_MS`); each author's messages per conversation pass a bucket (`FLOOD`: 400, then 20 a second), past which they are turned away and asked for again 2 s later (`floodRetry`). `inGroupWith` is one cached set, rebuilt when a group's member list changes. Every redial, `prune` drops profiles of people we share nothing with (friends, group members, those who left or were removed from our groups, and blocked people stay) and what non-members confirmed (`confirmed`), and clears memory-only per-peer records (`used`, `signalled`, `versions`, long-refilled `flood` buckets). Friend requests are announced with `announceRequest` (sealed, `src/shared/sealed.ts`) before the dial that rings, and resolved with `senderOf` (each look resolves at most 20 unknown keys, picked at random and in parallel, so junk keys on the topic cannot hold real requests back); search reads only published cards (`fetchCard`), which point to a thumbnail record under 1 KB made by `thumbnail` (index.ts, `nativeImage`); the exact friend ID is no longer announced (presence), username prefixes only with `settings.suggest`. **No Electron imports**, so tests run it directly |
| `src/main/network.ts` | One encrypted HyperDHT stream per peer, found by public key. Newline-delimited JSON `Wire` messages; `packet()` sends call datagrams (≤1000 B unreliable, larger over the stream). `dial(key, via)` links through a contact's blind relay (hyperdht `relayThrough`); `setRelay` runs ours (`blind-relay`'s server on a second key, `relayKeyPair`), accepting only our contacts and capped by `RELAY_LIMITS`. The DHT gets our identity as its default key so hyperdht's own relay dials show who we are. The server's firewall asks `admit` (node.ts: friends, group members, people we asked) before the handshake completes, so strangers never learn our address; a turned-away dial is reported as `knock`, which node.ts uses as a doorbell (`ring`: look for requests now; a dial from someone we asked looks for their acceptance now and again 3 s later). A dialed link that has received no bytes 3 s after `open` is dropped and dialed once more at once: hyperdht reports `open` before the other side answers, and that side may already have dropped the stream. `strict` is the test-only strict-router simulation |
| Relaying through a mutual friend (`node.ts`) | Settings.relay, on unless set to false (`relay !== false`), is only relaying for others: anyone can be reached through a relaying friend (`hello.via`, from 0.0.45; older copies accept relayed links only while relaying themselves). A contact's `hello.relay` says it relays (old versions never send it). For a peer with something pending (`demand`: unconfirmed messages, an open conversation, a call signal) whose direct dial failed, ask up to 3 relaying contacts `reach`; dial through the first yes. The dialer sends `relayed`; `State.relayed` makes call.ts send voice only and `probe` skip them. Only friends (and whoever a call signal is addressed to) are sought out this way (`need`), never every group member. Backoff per peer, also when nobody could relay yet, reset when a new relaying contact appears; redials back off too after 3 quick tries while relaying (`due`); a catch-up sends each message once per link (`sentUpTo`, cleared when the link closes); a peer's "you already had these" claim about our own messages is believed only up to `acked` (`heldFrom`); a relay going offline drops and retries its pairs at once; idle relayed links close after 10 min. Group members never linked with are named from their published card (`nameUnlinked`, each at most hourly). Tests: the `strict` tests in `test/node.test.ts` |
| `src/main/files.ts` | Shared files (no Electron imports). A `Msg` may carry `files` (`FileRef`: sha256, name, size, type, tiny preview; validated and signed in `src/shared/media.ts`/`sync.ts`); the bytes are pulled by hash in 64 KB `get`/`part` pieces over the peer link, 4 in flight, from a member of that conversation (the sender first), resumed from `files/<h>.part` and checked against the hash. Serves only members of a conversation the file is in, answering `nope` the same way to a guess. Pictures ≤25 MB fetch by themselves, the rest on request to a path from the save dialog; relayed links carry only those pictures. Sent files are referenced where they are (`addPath`), not copied; JPEG/PNG are re-encoded without metadata in `src/main/index.ts` (`attach`), which also serves checked files to the page as `eleusinia-file://<hash>` (inline types only). Tests: `test/files.test.ts` and the files test in `test/node.test.ts` |
| Activity (`src/shared/activity.ts`, `src/shared/steam.ts`, `src/main/activity.ts`, `src/renderer/Activity.tsx`) | What someone is playing, shared with friends and group members only, on unless Settings → Activity turns it off (`sharing`), each detail behind its own switch (`shareable`; the store details, genre, developer, release date and description, are off unless turned on); people can be hidden one by one. Plan and status: `docs/roadmap-activity.md`. `main/activity.ts` checks every 10 s: Steam's `RunningAppID` (Windows registry via `reg query`, `registry.vdf` elsewhere), then the running programs against `KNOWN_GAMES` and the user's own (`extra`). For a Steam game: the name from its `appmanifest`, playtime from `localconfig.vdf`, achievements from Steam's binary stats files (`achievementsOf`), genre, developer and description from the public store endpoint, rarity from the public global stats endpoint. Sent as `{ t: 'activity' }`, checked by `cleanActivity` (times moved onto our clock), memory only (`State.activity`, ours under our own key as friends see it). Fetches from Steam, Bungie.net and the art cache time out (10 to 15 s, `AbortSignal.timeout` in index.ts), so a hung request cannot stall the watcher. Peer numbers and text are clamped by `src/shared/clean.ts` (`num`, `str`). Pictures come only through `eleusinia-art://`, built from ids by `artUrl` (Steam's CDN), fetched by main and cached in `art/`. `ELEUSINIA_TEST_ACTIVITY` (a game as JSON) stands in for the watcher in the smoke run. CS2 and Dota 2: Valve's Game State Integration (`src/main/gsi.ts`, one server for both, told apart by `provider.appid`): Settings → Activity → the Steam tile's switch per game (`Connections` in `Activity.tsx`; the Bungie.net tile beside it) writes `gamestate_integration_eleusinia.cfg` into the game's `cfg` folder (Dota: `cfg/gamestate_integration/`, found through `steamAppDir`; Dota also needs the `-gamestateintegration` launch option, which Settings checks in `localconfig.vdf` via `steamLaunchOptions` and only explains, never sets), and the game POSTs to a server on 127.0.0.1 with the port and token kept in `gsi.json` (a taken or blocked port is swapped and the files rewritten; `status` says when each game was last heard and why posts were turned away, shown in the Steam panel); a game sending details counts as running even before the watcher sees it; `dotaOf` (`src/shared/dota.ts`) turns a Dota payload into `Game.dota` (hero, level, score, clock, stats; gold, items, health and buyback only with `DotaSettings.live`; a spectated match gives only the match); `cs2Of` turns a payload into `Game.cs2` (map, mode, score, round results, the phase clock as an end time, our stats and state; a watched player's numbers are never taken for ours), merged onto the Steam game in `index.ts` `startActivity` and dropped after 30 s of silence. Live health, money and weapon are shared only when turned on (`Cs2Settings.state`), since they would help an opponent. `ELEUSINIA_TEST_GSI_CFG` (one subfolder per game) stands in for the cfg folders in the smoke run. Destiny 2 (`src/main/bungie.ts`, `src/shared/destiny.ts`): the Bungie.net account is linked in the user's browser (bungie.net, then the return page in the mmhfn1.github.io repository, then a server on 127.0.0.1 for that one sign-in, its port in `state`); a confidential client, so a 90-day refresh token; the accounts come from the public `GetMembershipsById` (no extra scope) and nothing is kept until they are known; sealed with `safeStorage` in `bungie.json`; `GetProfile` every 5 s only while Destiny 2 is the game; Manifest definitions one by one (`neededDefs`, then `destinyOf`), cached in `bungie-defs.json` per Manifest version; pictures only from bungie.net's Destiny icon and activity picture folders (`BUNGIE_PATH`). `ELEUSINIA_TEST_BUNGIE` (a stand-in's address) makes linking approve at once in the smoke run. Marathon has no API yet: Steam only |
| `src/main/inbox.ts` | The developers' inbox (`npm run inbox`, which is the app started with `--inbox`): receives reports from anyone over the DHT, rate-limits (`reportLimit`: 20 an hour per sender and 100 an hour in all, since keys cost nothing), saves them and files GitHub issues with a token that only lives on that machine. See `docs/reports.md` |
| `src/shared/reports.ts` | Problem and crash reports: the scrubber every diagnostic line passes (`scrub`), report validation (`cleanReport`), the in-memory diagnostics (`createDiagnostics`) and the inbox key (`INBOX_KEY`). The main process keeps the diagnostics and sends crash reports; `node.ts` queues reports in `outbox/` until the inbox confirms them |
| `src/main/relay.ts` | Fallback when routers block direct WebRTC: a local UDP port offered to WebRTC as a low-priority `relay` candidate, with packets ferried over the peer link. Media stays DTLS-SRTP encrypted |
| `src/shared/protocol.ts` | Wire, state and event types; validation (`isKey`, `cleanProfile`, …); message stacking |
| `src/shared/sync.ts` | Signing and verification, group merge, missing-message calculation. Groups: the owner is proven by the id (`groupIdOf(owner, nonce)`), or for groups from before owners found once from the stored copy (`ownerOf`, on load in `node.ts`); members are those reachable from the owner through signed adds, minus signed leaves and the owner's signed removals (`signRemoved`); name and picture changes are signed (`signEdit`) and ignored more than `EDIT_AHEAD_MS` ahead. Without a known owner the old rules apply (every listed member counts) |
| `src/shared/updatesig.ts` | The update key (`UPDATE_KEY`), `verifyUpdate` and `updateFileFor`: every update file needs a signature over its version and SHA-512. Windows checks it in `src/main/index.ts` through electron-updater's `verifyUpdateCodeSignature` hook (it runs because `package.json`'s publish config names a `publisherName`); macOS and Linux install updates themselves (`src/main/selfupdate.ts`: electron-updater only finds them; the file is downloaded next to the running copy, checked, and swapped in for the .app bundle via `ditto`, or for the AppImage; Squirrel.Mac would need a paid Apple Developer ID). macOS builds are code-signed in `build/mac-sign.cjs` (electron-builder `afterPack`) with Eleusinia's own self-signed certificate (`MAC_CERT_P12`/`MAC_CERT_PASSWORD` secrets), ad hoc without it; `index.ts` asks once to move the app into Applications, where it can replace itself ("Not now" is remembered by a `not-in-applications` file in the data folder). `build/sign-update.cjs` signs in the release workflow with the `UPDATE_SIGNING_KEY` secret of the `release` environment; the private key never goes in the repository |
| `src/shared/callstate.ts` | Per-peer call decisions with no WebRTC imports: buffers early ICE candidates, decides when to restart ICE or rebuild (smaller key acts, with backoff; the larger key, on a failed connection, asks with `join` a few times (`ask`, `ASKS`) and then drops a peer who never offers, since that side may have reloaded), never while the peer's audio still arrives (`LinkHealth.flowing`) and later on long routes (`restartAfterFor`); also the SDP tweaks every description gets (`lightOpus`, `quickVideo`: video starts at 1 Mbps); `rejoinFrom`, the call to rejoin after restarting into an update (`restartForUpdate` in call.ts saves it in `localStorage`, good for 3 minutes). Tested in `test/callstate.test.ts` |
| `src/renderer/App.tsx`, `ui.tsx` | React UI: `App.tsx` is the shell, one place per action as the servers UI will need (Home: friend ID beside the search, friends, requests; no Home sidebar, groups are on the rail; a conversation's sidebar holds the group's identity and its voice room, `.room` listing who is in the call before joining, then Start or Join call, the only call button besides the rail's right-click; the chat header names the room, `Chat`, not the group again; `app-loading` until the first state; `Dialog` returns focus on close; questions before what cannot be undone are an `Ask` from common.ts, worded once (`removeFriendAsk`, `leaveGroupAsk`) and shown by ui.tsx `Confirm` wherever they are asked; style.css colours and tints only as `:root` tokens, spacing on a 4 px grid, type in whole pixels from 11, 12, 13, 14, 16, 20, 24, 28, 40) (home, profile, cards, conversations, the rail: the emblem is Home with its menu on right-click, plus an unadvertised Ctrl K; the rail itself is `Rail.tsx`: DMs with a message (`State.chats`, from node.ts `lastAt`, dated by log file on first start), pinned or closed through `Settings.pinned`/`closed`, a right-click `ContextMenu` per conversation, unread counts (node.ts `unread`, +1 per message from others and per missed call, `missedCall` from call.ts `unjoined`; `markRead` from Chat.tsx while the window has focus and the list is at its bottom; a call emptied by someone going offline waits a minute (`blips`) before it counts as missed, so a blip is not a second missed call), `Settings.nicknames` and `muted`, and `block` (node.ts: unfriends, refuses requests and links, uncounted, hidden in Chat.tsx; also from the profile panel, undone in Settings → Blocked people, `unblock`); groups renamed in place, `GroupName`, through node.ts `renameGroup`, which shares `editGroup` with the picture); `Settings.tsx` the Settings dialog and what opens from it; `Media.tsx` the call panel's pieces, share and camera dialogs, the stage (a joined stream, or our own share, carries the people row along its bottom: a tile per person, camera or picture, folded in localStorage `people-row-hidden`, folded sending no cameras), the Oculus (people in the call above the chat) and the ringing bar; `Chat.tsx` a conversation's messages, with links clickable (`MsgText`, `openLink` in index.ts: http and https only) and link previews (`LinkCard`; `useLinkDraft` asks main's `previewLink`, `src/main/links.ts`, while a link is typed: the page's first 512 KB and a picture re-encoded under 24 KB, fetched by the sender only; `Msg.link` is checked by `cleanLink` and signed apart as `lsig` in sync.ts so older copies still verify the message; tags read by `metaOf`, all in `src/shared/links.ts`, tested in `test/links.test.ts`); `Profile.tsx` the profile panel (`ProfilePop`) that `people.show(k, from)` opens beside the clicked element (portalled to the body, placed right, left, or below a wide row; Escape, a click elsewhere or the same element again closes it), with the banner (`ProfileBanner`, also on the full card), `GameGlance` from Activity.tsx, the volume while in our call and a message box to the DM; `people.show(k)` without an element opens the full card; `common.ts` what they share |
| `src/renderer/call.ts` | Calls: full-mesh `RTCPeerConnection` per participant, noise suppression (RNNoise from `@sapphi-red/web-noise-suppressor` in an AudioWorklet on its own 48 kHz context; the model is bundled inline since the page cannot fetch local files, and `index.html`'s CSP allows `wasm-unsafe-eval` and `blob:` for it; Chromium's own filter only when it is off; the smoke run turns it off because Chromium's fake microphone beeps a tone it rightly removes), offer/answer/ICE over `signal`, mute/deafen, device and bitrate changes, spare voice copies (RED negotiated first in `useSlots`, except through a friend's relay or above 64 kbps; Chromium cannot switch it mid-call), the voice and video holds (`jitterTarget`, `videoHold`, which rise at once and fall only by a clear step), connection sampling, screen sharing and cameras. Every connection has fixed slots from its first offer, found by order (`slotsOf`): voice, screen video, camera video, screen sound; `share`/`camera`/`voice` signals go only to the people in the call (`sendInCall`), `join`/`leave` to every member; `want` signals (`want` levels: `off` sends nothing, `audio` only a screen's sound, for a joined stream in a hidden window, `thumb`, `full`; a camera is `thumb` until a viewer asks for more, and a screen is `off` to everyone until they join it in `Stage`, one stream at a time; until then the sharer sends them a `preview` signal every 10 s, a small JPEG checked by `cleanPreview` in `video.ts`). Problem reports: each link's route is logged when it is first sampled and whenever it changes (`noteRoute`: through the chat link or direct, with how many direct routes answered), the grade line names loss and jitter per link (`trouble`), a voice arriving more than 5 % made up is logged (`patched`), and a Bluetooth hands-free microphone is logged and noted in the call panel (`handsFree`, all in `quality.ts`). Someone whose chat link closes stays in the call while their connection still works; they leave only when the watchdog drops it |
| `src/shared/video.ts` | Screen and camera decisions: quality choices up to the source's limits, bitrate, per-viewer encodings, the soft cap (`canStream`), what a camera can do (`cameraSource`). Plan for cameras and forwarding: `docs/roadmap-video.md` |
| `src/shared/idcard.ts` | Finding someone offline by exact friend ID: one DHT record per ID at a key pair anyone derives from the ID (`idSeed`), holding up to 6 claims, each a key and its signature over the ID; readers keep only claims that verify (`readClaims`). `node.ts` writes ours first (`publishId`, every 6 h with `announce`), rewrites friends' records to keep them alive (`keepFriendsFindable`), and `findFriend` adds the owners (`idOwners`) to the online lookup. Stored via `network.ts` `putShared`/`getShared`. Tests: `test/idcard.test.ts` and the offline-search test in `test/node.test.ts` |
| `src/shared/jingles.ts` | The app's sounds as notes (no audio files), each one distinct (tested), and `loopNow`: ringing and the caller tune for direct calls repeat for at most 40 s, and ringing becomes the soft `waiting` beeps while we are in another call (`ringingCalls` in call.ts feeds the bar App.tsx shows wherever we are). `src/renderer/jingles.ts` plays them on their own AudioContext; `call.ts` triggers them and notes each in the diagnostics (`sound: …`, which the smoke run checks) |
| `src/shared/hotkeys.ts` | Global hotkeys from raw key codes: when mute/deafen fire and push to talk starts or stops, and recording a combination. `src/main/index.ts` feeds it from `uiohook-napi` (a native system-wide key hook with prebuilt binaries; it is needed because Electron's own global shortcuts cannot see key releases, which push to talk needs) |
| `src/shared/speaking.ts` | Speaking ring decision (call.ts tells only `useSpeaking` subscribers in Media.tsx, not the whole window; message rows are memoized `MsgRow`s in Chat.tsx, member rows `MemberRow`s in App.tsx): RMS level against a threshold, with 250 ms hang time; mic sensitivity (`gate`, a threshold in dB with 400 ms hang). `call.ts` feeds it from an `AnalyserNode` per voice in one shared `AudioContext`, where voices also play through a per-person `GainNode` (0–200%) |
| `src/shared/sources.ts` | Which screens and windows the share picker offers: `kind` from the source id, and the filter for empty thumbnails, unnamed windows and known overlay/system windows (`HIDDEN_WINDOWS`, extend there). Applied in `src/main/index.ts` |
| `src/preload/index.ts` | Exposes `window.api.call`, `window.api.on`, `screens`/`chooseScreen` for the screen picker, `recordHotkey`/`stopRecording`, `win` for the page's own title bar buttons (the window has `titleBarStyle: 'hidden'`; `TitleBar` in `App.tsx`), and `isAdmin`/`restartAsAdmin` (Windows: relaunch elevated so hotkeys reach games run as administrator; all handled in `src/main/index.ts`) |

Data lives in the app's data folder as `state.json` plus per-conversation `.jsonl` message logs.

Key ideas worth keeping intact:

- A `Key` is a 64-hex ed25519 public key; it is the identity and the address on the DHT.
- Everything from another peer is untrusted: validate and cap it (see `cleanProfile`, `validGroup`, `verifyMsg`).
- Messages and group changes are signed by their author; a member's leave can only be signed by themselves.
- **Raise `CALL_VERSION` (`src/shared/protocol.ts`) in any change older copies cannot follow in a call** (slot order, signal meanings). Copies on different call versions then refuse to connect and say who must update, instead of failing silently. Every push to `main` reaches all testers as an update.
- The installed app updates itself from GitHub Releases (`startUpdates` in `src/main/index.ts`); `ELEUSINIA_UPDATE_URL` points it at another folder of releases for testing, `ELEUSINIA_NO_UPDATES=1` turns it off (the smoke run does).
- Tie-breaks use key order: when both sides dial or offer at once, the smaller key wins.
- Call signals are processed one at a time (`onSignal` queue) so ICE candidates never overtake their offer.
- Every local test DHT (smoke run, `test/node.test.ts`, `test/inbox.test.ts`) has 10 nodes on purpose: with 3, hyperdht's NAT check on the dialed copy often lacks samples, it aborts the hole punch it races against a LAN shortcut, and the dialer's link, already reported open, dies silently ~13 s later (see the comment in `test/smoke.mjs`); on the slower GitHub runner it also failed release checks.

## Conventions

- No semicolons, single quotes, 2-space indent, trailing commas in multi-line literals.
- Short functions; comments are brief and explain *why*, not what.
- Keep `node.ts` free of Electron and DOM imports; put pure logic in `src/shared/` so it can be unit tested.
- Prefer no new runtime dependencies; native modules need a good reason (they complicate packaging).
- Update `README.md` when a feature, limit or command changes.
